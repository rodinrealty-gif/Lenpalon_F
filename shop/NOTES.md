По решению заказчика в проект подставлены реальные данные Ленпалон Фэмили там, где они есть (бренд, юрлицо ООО «Биофлора», ИНН/ОГРН, адрес, телефон, e-mail, Telegram, промо-полоса, товар «Ленпалон Фэмили» за 9 700 ₽ со схемой приёма, тексты доставки/возврата, черновики политики/оферты/согласия). Всё остальное — плейсхолдеры макета без изменений.

- Добавлена категория **«Пищеварение»** (`digestion`): «Ленпалон Фэмили» не подходит ни под одну категорию макета. Чип появляется в фильтре каталога; бенто на главной (4 цели) не менялось.
- **Тексты макета, которые нужно проверить для Ленпалон Фэмили**: «Тест каждой партии», «Дозировки из исследований», «Независимые тесты каждой партии» (hero, принципы, пункты на странице товара), «Линейка для спорта», логотипы «Среди клиентов». Для Ленпалон Фэмили есть один протокол испытаний образца, а не каждой партии. Тексты оставлены как в макете (промт запрещает их менять) — заказчику решить.
- Дисклеймер «БАД не является лекарственным средством» заменён на «функциональная пищевая добавка, не является лекарственным средством» — так продукт оформлен в декларации.
- **Telegram** `t.me/lenpalon-family`: в именах Telegram дефис недопустим — ссылку нужно проверить.
- **Открытые вопросы заказчику**: состав капсул №1–4; документ соответствия на капсульную форму (декларация выдана на жидкую/порошкообразную форму во флаконах 23 мл).

## Визуал

1. **Шапка переносится до ≤899px**, а не ≤767px как в макете: с названием «Ленпалон Фэмили» строка шапки не помещается на 768–899px даже без отступов. На ≥900px — как в макете.
2. **Токен `--danger` (#B42318)** — для ошибок формы подписки; в макете состояний ошибки нет.
3. **Диалог поиска** в макете не нарисован — собран из токенов и классов макета (`.field`, `.iconbtn`, радиус 14px).
4. **Кнопка «−» неактивна при количестве 1** (визуально opacity 0.4) — промт требует минимум 1, disabled честнее, чем немая кнопка.
5. **`.lift:hover .arrow`** в макете вне `prefers-reduced-motion`; по промту перенесено внутрь `no-preference`.
6. **`role="listitem"`** в «С этим покупают» в макете стоит на `<article>` (недопустимая роль) — вынесен на обёртку.
7. **Ссылка «Согласие на обработку данных»** добавлена в юридическую строку подвала (отдельный документ согласия по 152-ФЗ).
8. **Ссылки-фото товаров**: доступное имя через `aria-label` с названием (как требует промт). Пока стоят текстовые заглушки, Lighthouse отмечает `label-content-name-mismatch` (видимый текст заглушки ≠ имя ссылки); с реальными фото предупреждение уйдёт.
9. **Скрытая «картинка» без src** (`PhotoSlot` без ссылки) — `role="img"` + `aria-label="Место для фото: …"`, как в макете.

## Поведение

- **`aria-current="page"`**: на главной не ставится ни на один пункт — у главной нет своего пункта меню («Цели» — якорь на главной, это не страница). Каталог и товары — «Каталог», `/lab` и `/about` — свои пункты.
- **«Цели»** ведёт на `/#goals` (бенто на главной). **Кабинет** и **корзина** — страницы-заглушки `/account`, `/cart` (в `robots.txt` закрыты, `noindex`): ссылки в макете были, а страницы корзины по промту не делаем.
- **Сортировка по цене**: цены в данных — `number | null`. Товары без цены (плейсхолдер `[ЦЕНА]`) всегда в конце, в исходном порядке.
- **Плитка показывает цену упаковки по умолчанию** (средней), а не «от».
- **Цена по подписке** считается, только если заданы и цена, и `discountPercent`; иначе показывается та же цена с пометкой «со скидкой по подписке».
- **Подбор**: без JS форма отправляется на `/catalog` (GET), с JS — `resolveQuiz()` по ключевым словам. Добавлены слова для «Пищеварения».
- **Подписка**: без `PUBLIC_NEWSLETTER_ENDPOINT` ничего не отправляется (имитация успеха + `console.info`).
- **FAQ**: все ответы в HTML (видны поисковикам), вкладки с автоактивацией при навигации стрелками; ←→ работают как ↑↓.
- **`/catalog?cat=…` без JS** показывает все товары (статическая генерация не видит query); фильтр применяется скриптом.
